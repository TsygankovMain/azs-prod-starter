## 1. Контекст и проблема

Фотолента — экран проверяющего: тайлы фото-отчётов АЗС, лайтбокс со свайпами, отправка «замечаний» по фото. Текущие компоненты: `frontend/app/components/photos/PhotoFeedView.vue`, `PhotoFeedGrid.vue`, `PhotoLightbox.vue`, `RemarkDraftPanel.vue`, `RemarkJournal.vue`.

Три замечания с прода:

1. **FEED-1.** На смартфоне фото нельзя увеличить — деталей не рассмотреть. В `PhotoLightbox` фото отрисовано `object-contain pointer-events-none`, масштабирования нет.
2. **FEED-2.** Пересылать фото нужно конкретному человеку (Баташков, Мальцева, Тузов), а текущие «замечания» уходят только управляющему/администратору АЗС по ролям (`RemarkDraftPanel` — два фиксированных получателя).
3. **FEED-3.** В подписи только «Название» карточки = «АЗС 82» (номер) — стороннему непонятно, что за точка.

## 3. FEED-1 — Мультитач-зум в лайтбоксе

### UX
- **Мобильный:** пинч двумя пальцами — плавный зум 1×…5×; **двойной тап** — переключение 1× ↔ ~2.5× в точке тапа; при увеличении (scale > 1) одним пальцем — панорамирование (pan); индикатор кратности «2.4×» сверху + сброс к 1× (тап по индикатору или двойной тап).
- **Десктоп:** колесо мыши — зум к курсору; двойной клик — toggle; зажатие+перетаскивание — pan.
- **Сброс:** при переходе к другому фото scale сбрасывается в 1×.

### Конфликт со свайпом (ключевое)
Сейчас свайп между фото — pointer-события с порогом 50px (`PhotoLightbox` `onPointerDown/Up`). При зуме это конфликтует с pan.
**Правило:** навигация свайпом активна **только при scale == 1**. При scale > 1 горизонтальный drag = pan внутри фото, смена фото отключена (только стрелки/клавиши). Стрелки‑кнопки и клавиатура работают всегда.

### Реализация
- **Решение (рекомендованное):** нативно на Pointer Events — отслеживание 1–2 активных указателей; при двух — расстояние между ними → scale; transform `translate()+scale()` на обёртке `<img>`. Без тяжёлой библиотеки (бандл, B24-окружение, контроль над конфликтом со свайпом). Границы scale 1–5, clamp pan по краям.
- **Альтернатива:** библиотека panzoom (cdn). Отклонена: лишний вес + свой конфликт со свайпом всё равно разруливать.
- **Файл:** `PhotoLightbox.vue` — блок «Основное фото» (сейчас `<img class="object-contain pointer-events-none">`): обернуть в zoom-контейнер с состоянием `scale/tx/ty`, обработчиками pointer/wheel/dblclick; кнопка‑индикатор кратности; гейт свайпа по `scale === 1`.

## 4. FEED-2 — Пересылка фото любому получателю

### UX
- В лайтбоксе рядом с «Отметить» — кнопка **«Переслать»**.
- Выбор получателя двумя вкладками:
  - **Роли АЗС** — как сейчас (управляющий / администратор; `getPhotoRecipients`).
  - **Сотрудник Б24** — поле поиска → список сотрудников портала → выбор одного.
- Комментарий к фото (механика уже есть: пофотный коммент в лайтбоксе/`RemarkDraftPanel`).
- Отправка — в **личный чат** выбранного получателя (фото + текст), тем же каналом, что и текущие замечания.
- На десктопе — модалка рядом с фото; на мобильном — нижний лист (см. мокап).

### Backend
- **Поиск сотрудников (новый):** `GET /api/users/search?q=` → `user.search` (или `user.get` с фильтром) под admin-OAuth-контекстом; вернуть `[{id, name, position}]`, лимит + дебаунс на фронте. Только активные сотрудники.
- **Отправка (расширение `sendPhotoRemark`):** обобщить получателя — `recipientType: 'manager' | 'admin' | 'user'`, при `'user'` — `recipientUserId`. В личный чат произвольного `userId` — тем же механизмом, что текущая доставка (`imbot.message`/`im` File.upload, `dialogId = userId`). Роли остаются для обратной совместимости.
- **Хранение/журнал (`photo_remark`):** добавить `recipient_user_id` (nullable) + `recipient_name`; `RemarkJournal` показывает произвольного получателя. Миграция таблицы — аддитивная (nullable-колонки), без потери данных.

### Frontend
- `RemarkDraftPanel.vue` — добавить вкладку «Сотрудник» с поиском (переиспользовать паттерн debounce-поиска); при выборе сотрудника — `selectedRecipient = {type:'user', id, name}`.
- `stores/api.ts` — методы `searchUsers(q)` и расширение `sendPhotoRemark` под `recipientType/recipientUserId`.

## 5. FEED-3 — Подпись: название + адрес

### Решение
Подпись = **название (title) + адрес**. Название — стандартное «Название» карточки (`azsTitle`, как сейчас). Адрес — поле карточки АЗС **`UF_CRM_10_1773914353`** («Адрес»). Формат: «{title} · {адрес}» (на узких экранах — второй строкой). Если адрес пуст — только title.

### Backend
- Резолвер названий АЗС (`createAzsTitleResolver` / `batchResolveAzsTitles`, `reportsRoutes.js`) — добавить `UF_CRM_10_1773914353` в `select`; возвращать `{ id, title, address }`.
- Прокинуть `azsAddress` в элементы там, где формируется подпись: фид (`photoFeedRoutes.js`), день-фото/витрина (`analyticsRoutes.js`), карточка.

### Frontend
- Тип `PhotoFeedItem` += `azsAddress?: string | null`.
- Подписи в `PhotoFeedGrid.vue` (тайл + заголовок группы), `PhotoLightbox.vue` (нижняя подпись) — выводить «title · address» (fallback на title).

## 7. Тестирование

**Backend (node:test):**
- Резолвер АЗС: при наличии `UF_CRM_10_1773914353` возвращает address; при пустом — только title.
- `searchUsers`: маппинг ответа `user.search`; пустой запрос/нет прав → корректная деградация.
- `sendPhotoRemark` с `recipientType:'user'`: доставка в личный чат `userId`; журнал пишет `recipient_user_id/name`; роли (manager/admin) — без регресса.
- Миграция `photo_remark`: аддитивная, идемпотентная, старые записи читаются.

**Frontend:**
- `npm run lint`.
- **Ручной смоук (обязателен):** зум-жесты автотестами не покрываются (нет рантайм-харнесса фронта — known gap проекта). Проверка на **реальном смартфоне (iOS + Android)**: пинч, двойной тап, pan, что свайп не срабатывает при зуме; пересылка сотруднику доходит в личный чат; подпись показывает адрес.

## 8. Риски и открытые вопросы

- **FEED-1 главный риск:** жесты зума ↔ свайп. Митигировать строгим гейтом «свайп только при scale==1» + смоук на реальных устройствах (не эмулятор).
- **FEED-2:** объём портала при поиске сотрудников — лимит + дебаунс; права admin-контекста на `user.search`.
- **FEED-3:** если `UF_CRM_10_1773914353` у части карточек пуст — фоллбэк на title (без поломки).
- **Производительность:** добавление UF в `select` резолвера не плодит запросов (тот же batch).
